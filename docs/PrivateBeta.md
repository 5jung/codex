# 비공개 테스트 배포 준비

사용자 결정: 소규모 비공개 테스트. 현재 외부 서버에 배포하거나 유료 자원을 만들지는 않았다.

## 검증된 범위
- linux/amd64 Node 24 고정 digest 기반 다단계 Docker 이미지 빌드.
- MariaDB 11.4와 앱 컨테이너를 격리된 테스트 구성으로 실행.
- 초대 자격정보 없는 요청 401, 올바른 초대 자격정보 있는 페이지/API 200.
- 컨테이너 API에서 공식자료 429건 확인, 없는 API는 JSON 404.
- 개발 DB를 백업한 뒤 별도 임시 DB로 복원해 시설 429건을 확인하고 임시 DB 삭제.
- 실제 외부 도메인·HTTPS 인증서 발급·휴대폰 외부 접속은 아직 미검증.

## 배포에 필요한 것
Docker Compose를 실행할 linux/amd64 서버와 도메인이 필요하다. 서버 제공사·계정·비용은 아직 선택하지 않았다. 도메인 DNS가 서버를 가리켜야 하며 80/443만 외부 공개하고 DB 포트는 공개하지 않는다.

실제 자격정보는 저장소 밖의 권한 0600 환경 파일이나 배포 서비스의 비밀 설정에 등록한다. 이 저장소에 값이 포함된 .env 파일을 만들거나 채팅에 값을 보내지 않는다.

필요 변수:
- VITE_KAKAO_MAP_KEY: 브라우저용 JavaScript 키. 공개 번들에 포함되므로 카카오 도메인 제한을 적용한다.
- DB_ROOT_PASSWORD, DB_PASSWORD: 각각 다른 긴 무작위 값.
- BETA_USER, BETA_PASSWORD: 별도의 초대용 자격정보. BETA_PASSWORD는 16자 이상. 테스트 사용자에게 안전한 채널로 전달하고 종료 시 교체한다.
- BETA_DOMAIN: 실제 테스트 도메인.
- APP_ORIGINS: `https://실제테스트도메인`.

기본 app 포트는 서버의 loopback 8080에만 바인딩한다. 이 상태의 HTTP 연결은 컨테이너 검증용이며 외부 사용자에게 공개하지 않는다. HTTPS 프로필을 켜면 Caddy가 TLS를 종료하고 내부 앱에 전달한다. 앱 계정 세션은 production 모드에서 Secure 쿠키를 사용한다.

```sh
# 환경 파일 경로는 실제 서버에 맞게 변경한다.
docker compose --env-file /secure/nursing-beta.env build
docker compose --env-file /secure/nursing-beta.env --profile https up -d
```

현재 클라우드처럼 빌드 네트워크에 프록시가 있으면 HTTP_PROXY/HTTPS_PROXY/NO_PROXY를 Docker 표준 build arg로 전달하고, 환경이 제공한 CA bundle을 `proxy_ca` BuildKit secret으로 제공해야 한다. Dockerfile은 해당 CA로 npm TLS 검증을 유지한다. 일반 서버에서는 이 secret이 필요하지 않다. HOME 쓰기가 제한된 환경은 BUILDX_CONFIG를 작업공간의 쓰기 가능한 경로로 지정한다. 프록시 값·키 값이 들어간 명령을 출력하거나 HAR/trace를 저장하지 않는다.

카카오 개발자 콘솔에 실제 HTTPS 도메인을 등록하고 가입·로그인·복구·탈퇴·후기·신고·제보·검토·길찾기를 실제 테스트 도메인에서 다시 확인한다. 초대 자격정보와 앱 계정은 별개다. 검색 로봇 차단 헤더는 접근 인증을 대신하지 않는다.

## 계정과 데이터 운영
가입 시 1회 표시되는 복구 코드는 해시만 DB에 저장한다. 복구에 사용하면 새 코드로 교체하며 모든 세션을 만료한다. 비밀번호 변경도 모든 세션을 만료한다. 복구 코드를 잃은 사용자를 이메일로 복구하는 기능은 없다. 가입·복구 화면에서 이를 안내한다.

회원 탈퇴는 비밀번호와 삭제 확인을 요구한다. 계정·세션·후기·신고·제보를 삭제하고 이미 승인되어 시설에 반영된 사실 정보는 유지한다. 관리자는 권한 인계 후 별도 관리 절차가 필요하며 셀프 탈퇴를 차단한다. 운영자 신원·연락처·개인정보 처리와 백업 보관 기간은 테스트 시작 전 확정해야 한다.

데이터 동기화는 제공 범위가 명시된 출처만 대상으로 한다. 새 원본에서 빠진 시설은 DB에서 비공개 처리하되 후기와 이력은 바로 삭제하지 않는다. 다시 나타나면 활성화한다. 빈 전체 스냅샷은 실수로 전체 시설을 숨기지 않도록 거부한다. 출처에서 시설명이 바뀌면 새 ID가 생길 수 있어 동일 시설 연결은 별도 검토가 필요하다.

개발 DB 백업·격리 복원 검증:

```sh
python scripts/backup-db.py --verify-restore
```

현재 helper는 개발 컨테이너 nursing-mariadb를 대상으로 한다. 운영 컨테이너의 백업 자동화는 실제 서버 선택 후 경로·접근 제어·암호화·보관 기간과 함께 구성한다. 운영 DB에 테스트 명령을 실행하지 않는다.
